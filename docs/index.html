Features

Everything an agent needs, in one place

gai covers the whole path from a model call to a production agent: tools, memory, orchestration, an API with keys and budgets, and a UI to watch it all.

Any model

Anthropic, OpenAI-compatible APIs and local models through one provider/model name, with retry, fallback, metering and a cost-aware router.

Tools & MCP

Built-in tools plus any MCP server over stdio or HTTP, with OAuth sign-in and per-tool approval policies.

Browser & code sandbox

Agents drive a real headless Chrome under domain rules, and run Python, JavaScript or bash in a throwaway container with no network.

Personas

Reusable, versioned voices with tone, rules, examples, an avatar and a greeting, for any agent or a single chat.

Rust SDK & bundles

Embed the whole platform with a builder and #[gai::tool], and move agents between servers as .gaibundle files with no secrets inside.

Memory & RAG

Self-editing memory blocks, archival memory, and knowledge collections with hybrid vector + keyword search over docs and PDFs.

Multi-agent workflows

Agents delegate to each other, and YAML DAG workflows add parallel nodes, fan-out, conditions, retries and human approval steps.

Durable & replayable

Runs survive restarts. Fork any run from any step with a new model, prompt or tools, and compare the results side by side.

Versioned specs

Every save of an agent or workflow is an immutable version you can diff, label and roll back to.

Triggers

Start agents and workflows on cron schedules, signed webhooks or file changes, with no double-firing.

Media

Speech-to-text, text-to-speech and image generation as agent tools and API endpoints.

Interop

Expose your agents as an MCP server or over A2A, and call remote A2A agents as tools or delegates.

Agents as config

A few lines of YAML

An agent is a model, a prompt and what it may use. gai handles the loop, approvals, budgets and context.

  • Tools by name or glob, MCP tools included
  • Knowledge scopes RAG search to your collections
  • Delegates turn other agents into ask_<name> tools
  • Limits cap steps, tokens and spend per run
researcher.yaml
model: anthropic/claude-sonnet-5-5
description: Researches a topic and writes a brief.
system: You are {{ agent }}. Today is {{ date }}.
tools: [http_fetch, rag_search]
knowledge: [handbook]
delegates: [writer]
memory:
  blocks:
    - { label: notes, value: "" }
limits:
  max_steps: 20
research-brief.yaml
name: research-brief
inputs:
  topics: { default: [webgpu, wasm] }
nodes:
  - id: research
    map: inputs.topics
    agent: researcher
    input: "Research {{ item }}"
  - id: review
    human: "Approve the notes?"
    needs: [research]
  - id: brief
    agent: writer
    input: "{{ nodes.research.output }}"
    needs: [review]
Workflows

Orchestrate many agents

Workflows are checkpointed DAGs. A crash or restart picks up where it left off, without repeating finished work.

  • Node types: agent, tool, template, value and human
  • map fans out over a list in parallel
  • if, retries and timeouts on any node
  • Live DAG view in the dashboard
Providers

Bring any model

Presets are built in; set the provider's API key and use provider/model. Anything OpenAI-compatible can be declared in gai.toml.

Get started

Running in a minute

Requires Rust 1.91+. Everything works offline with the built-in mock/echo model, so you can try it before adding a key.

1

Build

$ git clone https://github.com/aksh-b/gai.git
$ cd gai && cargo build -p gai-cli
2

Try it offline

$ cargo run -p gai-cli -- workflow run examples/workflows/hello.yaml
3

Add a model and chat

$ export ANTHROPIC_API_KEY=...
$ cargo run -p gai-cli -- chat -m anthropic/claude-sonnet-5-5
4

Serve the API and dashboard

$ cargo run -p gai-cli -- serve
  → http://localhost:8484  ·  API docs at /docs

Or as one container: docker build -t gai . then docker run -p 127.0.0.1:8484:8484 -v gai-data:/data gai serve --local.
